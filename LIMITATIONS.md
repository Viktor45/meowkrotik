# Ограничения meow-rs по сравнению с mihomo

Документ перечисляет **только то, от чего придется отказаться** при переходе с
mihomo (Clash Meta) на meow-rs в контейнере meowkrotik. Всё, что работает, здесь
перечислено только одним разделом в самом конце, чтобы не мешать.

Проверено на **meow-rs v0.29.0** (релиз 2026-11-05) — релизными бинарниками
`full`-сборки, прогоном `meow -t` и живым стартом. Формулировки сверены с
[миграционным документом meow-rs](https://github.com/meow-rs/meow-rs/blob/main/docs/migration-from-go-mihomo.md),
[документом по TUN](https://github.com/meow-rs/meow-rs/blob/main/docs/tun.md) и
[описанием совместимости API](https://github.com/meow-rs/meow-rs/blob/main/docs/mihomo-api-compatibility.md).
Там, где поведение менялось после 0.22.0, это указано явно.

Главная особенность meow-rs по сравнению с mihomo: часть привычных конструкций
ядро не понимает, но и не отвергает, а молча игнорирует; часть же, наоборот,
останавливает запуск с ошибкой. Ядро различает два класса расхождений
([ADR-0002](https://github.com/meow-rs/meow-rs/blob/main/docs/adr/0002-upstream-divergence-policy.md)):

- **Класс A** — жёсткая ошибка: конфиг не грузится вообще.
- **Класс B** — предупреждение и пропуск: конфиг грузится, но объект не
  работает.

Ключ `strict: true` (верхнего уровня) превращает любой пропуск класса B в
ошибку класса A. Это единственный способ узнать о тихих пропусках на этапе
загрузки — для production-конфигов его стоит включать.

## Как читать этот документ

Обозначения в таблицах:

- **нет** — функции в meow-rs не существует, попытка использовать даст ошибку
  загрузки конфига или отказу соединения;
- **частично** — функция есть, но с заметно меньшим охватом или иной семантикой;
- **иначе** — функция работает, но поведение отличается от mihomo, и это важно.

## Подписки и прокси

### Формат подписки

В mihomo провайдер прокси умеет разбирать три формата: Clash YAML, построчный
список URI (`vless://`, `ss://`) и base64-подписку, в которую упакованы те же
URI. meow-rs понимает **только Clash YAML** — список `proxies:` или голый список.
Остальные два формата разбираются «в ноль» без ошибки: в панели и в логе видно
`count=0`, группа пустая, соединения не идут.

Практическое следствие: если ваша панель отдает несколько форматов, нужно
выбрать ссылку «Clash». Если отдает только base64 или URI — подписку придется
перегенерировать в Clash-формате либо скормить ядру список прокси вручную.

Ограничение относится и к содержимому файлов провайдеров: файл `type: file`
должен быть YAML со списком `proxies:`; строки `vless://` в нем ядро не
разбирает.

С 0.27 парсер YAML другой (`serde-saphyr` вместо заброшенного `libyaml`), и
появляется подводный камень содержимого: **числоподобный `password` без
кавычек** (`password: 000000`) теперь разбирается как число, и узел
**отбрасывается** с предупреждением `Failed to parse proxy: missing password`
(в `proxies:` верхнего уровня при `strict: true` — ошибка загрузки). mihomo с
yaml.v3 держит такое значение строкой. Узлы в подписке с таким паролем
выпадают молча, по одному предупреждению на узел — лечится кавычками
(`password: "000000"`) на стороне панели или заменой узла.

### Разбор YAML (с 0.27 — serde-saphyr)

Ядро перешло с заброшенного `libyaml` (RUSTSEC-2024-0449) на чистый
Rust-парсер `serde-saphyr`. Расхождения с mihomo и со старым парсером:

- **Дубликат ключа в маппинге — жёсткая ошибка разбора**:
  `duplicate mapping key: mixed-port ... at line 3, column 1`. mihomo
  (yaml.v3) молча оставлял последнее значение. Это касается и конфига, и
  payload'ов провайдеров, и подписок.
- **Цепочки merge-ключей теперь раскрываются**: якорь, внутри которого есть
  свой `<<:`, больше не ломает загрузку `missing field 'type'` — раскрывается
  вся цепочка (в 0.22–0.26 это было ошибкой, и шаблоны писали якоря
  целиком). `<<: null` теперь тихо сливает пустоту вместо ошибки.
- Скаляры разрешаются по YAML 1.1-правилам saphyr: `0123` читается как число
  `123.0` (yaml.v3 держал строкой), `1_000` — как `1000`, смешанный регистр
  `TrUe`/`nUll` — как булево/null. Для типизированных полей конфига
  (`secret: 000000`) значение доезжает как строка в исходной записи; для
  узлов в подписке см. числоподобный `password` выше.
- Документы глубже 32 уровней вложенности отвергаются бюджетом парсера;
  `!tag`-узлы в недоверенных документах (подписки, провайдеры) отбрасываются.
- `hosts:` и `nameserver-policy:` сохраняют порядок документа; коллизии в
  одном слоте три (`x` против `+.x`) решает последний записавший, а не
  бросок монеты при старте.

### Локальные серверы SRV

В контейнере mihomo переменная `SRV<n>` принимала URI-ссылку на прокси
(`vless://...`). Здесь она принимает **однострочный YAML-мэппинг**:

```
SRV1={name: nl-1, type: vless, server: example.com, port: 443, uuid: ..., tls: true, flow: xtls-rprx-vision, network: ws, udp: true}
```

То есть перенос конфигурации с mihomo-контейнера потребует переписать все
локальные серверы из URI в YAML. Готовые примеры есть в README.

### Протоколы исходящих

| Протокол | Статус | Что именно не так |
| :--- | :--- | :--- |
| TUIC | нет | Адаптера не существует. Узел типа `tuic` не разбирается и пропускается с предупреждением (в `strict: true` — ошибка) |
| WireGuard | нет | То же |
| SSH | нет | То же |
| ShadowsocksR | нет | То же |
| TrustTunnel | нет | Протокол **не входит** в релизную сборку `full` — это отдельная cargo-фича `trusttunnel`, которую надо включать при сборке. В готовом бинарнике узел не разбирается с предупреждением |
| AnyTLS | работает | Только в сборке `full`; релизные бинарники ее содержат. `minimal`-сборка — ошибка |
| Snell v1/v2 | нет | Поддерживаются только v3, v4, v5, v6. V1/v2 — не разбираются |
| Входящий Shadowsocks (`listeners: - type: shadowsocks`) | работает | С 0.27 фича `listener-shadowsocks` входит в `full`, и релизные бинарники **принимают** такой listener (в `minimal` его по-прежнему нет). Учетных записей у входа нет: авторизация — один общий `password` из конфига |

Поддерживаются полностью или с покрытием mihomo: Shadowsocks (включая AEAD
2022, встроенные плагины `v2ray-plugin`/`gost-plugin`, `shadow-tls`, `restls`,
`jls`, `kcptun`, внешние SIP003-плагины), Trojan, VMess, VLESS, Hysteria2,
Snell v3–v6, HTTP CONNECT, SOCKS5, direct, reject. С 0.28 `v2ray-plugin`
сам фреймует поток в Mux.Cool (как клиент и mihomo): сервер на дефолтных
опциях работает без `mux:`; для сервера, запущенного с `mux=0`, укажите
`mux: false`.

### VLESS

| Поле | mihomo | meow-rs |
| :--- | :--- | :--- |
| `flow: xtls-rprx-direct` | принимается (давно помечено устаревшим) | узел **не разбирается** с предупреждением; в `strict: true` — ошибка. Поддерживается только `xtls-rprx-vision` |
| `flow: xtls-rprx-splice` | принимается | То же |
| `flow: xtls-rprx-vision` на `network: ws`/`grpc`/`h2`/`httpupgrade`/`xhttp` | грузится, каждое соединение падает с «failed to use vision» | узел **не разбирается** с предупреждением: Vision требует `network: tcp` с `tls: true` или REALITY |
| `encryption:` кроме пустого/`none`/`mlkem768x25519plus...` | принимается | узел **не разбирается** с предупреждением: других шифров тела VLESS не существует |
| `encryption: mlkem768x25519plus...` (постквантовая) | принимается | работает в релизной сборке, но отсутствует в `minimal` |
| `tls: false` без внешнего шифрования | молча | предупреждение один раз при загрузке: трафик открытый |
| `smux: {enabled: true}` | мультиплексирование smux | реализовано как sing-mux (smux/yamux/h2mux, по умолчанию h2mux) и Mux.Cool для Xray; ключ `mux:` принимается |
| входящий VLESS | есть | **отложен**, не реализован |

Обратите внимание на формулировку. Сам разбор узла — ошибка класса A: ядро
понимает `flow` и `encryption` как недопустимые значения. Но **узел** при этом
не разбирается: в провайдере он отбрасывается с предупреждением
`failed to parse proxy`, в разделе `proxies:` верхнего уровня — то же самое с
предупреждением, а конфиг в целом **грузится**. В `strict: true` любое из
этих мест превращается в ошибку загрузки. Проверено на 0.26.1–0.28.0: подписка с
одним `flow: xtls-rprx-direct` дает `Config loaded: proxies=8` вместо 9 и
предупреждение в логе. Для конфигов, где важна целостность состава подписки,
включайте `strict: true`.

### SOCKS5 и HTTP как исходящие

- `socks5` с `udp: true`: **работает**. Ядро поднимает UDP ASSOCIATE и
  пересылает дейтаграммы. Через `dialer-proxy` цепочку UDP не везти — там
  ожидаемый отказ `NotSupported`.
- У `socks5` и `http` задан только `username` без `password` — **жёсткая ошибка
  загрузки** (в mihomo поведение не определено).
- У исходящего `http` поддерживается только Basic-аутентификация прокси; Digest и
  NTLM не работают.

### direct и multi-WAN

В mihomo узел `type: direct` умеет привязывать соединение к интерфейсу, к
версии IP и к метке маршрутизации:

```yaml
- name: WAN2
  type: direct
  interface-name: eth1
  ip-version: ipv4
  routing-mark: 100
```

**В meow-rs эти три поля не реализованы.** Узел разбирается, поля
молча игнорируются, и весь трафик уходит в интерфейс по умолчанию. Работает
только **верхнеуровневый** `routing-mark:` — он применяется ко всем исходящим
соединениям ядра.

Практическое следствие для meowkrotik: модель multi-WAN через VETH, которую
собирает `entrypoint.sh` из переменных `GATEWAY_<IP>`/`GATEWAY_<IFACE>`,
**не работает**. Дополнительный veth публикуется как прокси `type: direct`, но
не привязывает свой трафик к своему интерфейсу. Для раздельных маршрутов нужен
собственный `ip rule`/`ip route` на стороне роутера либо ядро, собранное с
поддержкой этих полей.

## Прозрачный вход: TUN и tproxy

Это самая заметная по объему правка: в mihomo TUN — один из типов входа в
массиве `listeners:`, в meow-rs — **отдельная секция верхнего уровня**.

### TUN

| Что | В mihomo | В meow-rs |
| :--- | :--- | :--- |
| Формат | `listeners: - type: tun` | секция `tun:` верхнего уровня. Тип слушателя `tun` — **жесткая ошибка** |
| `inet4-address` | список адресов | **строка**; список — ошибка типа |
| `inet6-address` | список адресов | строка или список (берется первый элемент); учитывается **только** вместе с `auto-route: global` |
| `auto-route` | bool | `true` / `false` / `fake-ip` / `global`. С 0.27 `true` — это **полный перехват**: весь трафик самого хоста идет в устройство (IPv6 — с `inet6-address`), `dns-hijack` включается по умолчанию, исходящие сокеты ядра привязываются к физическому интерфейсу. На Linux дефолтные маршруты устройства живут в отдельной таблице, и в устройство уходят policy rules только для **собственного** трафика хоста; транзитный (форвард) остается в главной таблице, где в устройство по-прежнему завернут только fake-ip диапазон. `fake-ip` сохраняет старый узкий охват |
| `inet4-address` не задан | адрес `172.19.0.1/30` | С 0.27 по умолчанию — первый /30 от `dns.fake-ip-range` (для дефолтного диапазона `198.18.0.1/30`), чтобы не пересекаться с docker-сетками |
| `stack`, `strict-route`, `auto-redirect`, `auto-detect-interface` | работают | принимаются с предупреждением и **игнорируются** (`tun.<поле>: field is not supported in meow-rs and will be ignored`). Тот же прием сделан для `endpoint-independent-nat`, `mtu-v6`, `route-address`, `route-exclude-address`, `include-uid`, `exclude-uid`. А вот `disable-icmp-forwarding` ядро не знает вовсе — поле проходит как неизвестное, без предупреждения |
| Что заворачивается в устройство | весь трафик по маршрутам | у **транзитного** трафика (форвард с роутера) — **только fake-ip диапазон**: соединения по IP-литералам без DNS в устройство не попадают. Свой трафик хоста с `auto-route: true` перехватывается целиком |
| Имя входа для `IN-NAME` | задается в конфиге | всегда `meow-tun`, жестко зашито в ядре, значение `device` на это не влияет |
| Требования | — | обязательно DNS в режиме fake-ip и root/`CAP_NET_ADMIN` |

Практическое следствие для роутера: маршрутизация по IP-адресам (обращение к
ресурсу напрямую, без разрешения имени) в TUN meow-rs по-прежнему не попадает —
транзитный поток без fake-ip идет по обычным маршрутам. Это не ошибка
конфигурации, это архитектурное свойство userspace-стека.

### tproxy

| Что | В mihomo | В meow-rs |
| :--- | :--- | :--- |
| `udp: true` вместе с управляемым файрволом | работает | **только с `firewall: false`**: ядро само не ставит правила для UDP TPROXY, маршрутизацию обеспечивают внешние nft-правила |
| Сокет `tproxy-port` | перехватывает TCP и UDP | перехватывает **только TCP**. Направленный на него UDP молча уходит в никуда |
| UDP через tproxy | v4 и v6 | **только IPv4**, только Linux, только в пределах `prerouting` |
| `redir-port` | есть | **не поддерживается**, только `tproxy-port` |
| Логика файрвола | верхнеуровневый блок `iptables:` по умолчанию **выключен**, правилами управляет администратор | ключ `firewall:` живёт на записи tproxy в `listeners:` и по умолчанию **включен**; сокет `tproxy-port` всегда управляемый |
| Блок `iptables:` верхнего уровня | работает | **молча игнорируется** — такого ключа в конфиге meow-rs нет, лишние верхнеуровневые ключи просто отбрасываются (это не эквивалент `firewall:`) |

Последний пункт — источник типичной ошибки при миграции. Конфиг, который в
mihomo работал с правилами, которые администратор ставил сам, в meow-rs начнет
создавать собственную таблицу `inet meow_tproxy_<pid>_<seq>` рядом с
администраторской. Лечится явным `firewall: false` на записи tproxy. С 0.28
управляемый файрвол meow сам не заворачивает UDP/53 в TPROXY (для tproxy с
`firewall: false`, как в этом контейнере, правила — целиком на стороне
entrypoint, и запросы к DNS самого роутера отсекаются правилом
`fib daddr type local`, так что разрыва DNS нет).

С 0.28 входы проверяют **имя назначения**: хост обязан быть IP-литералом или
DNS-именем (буквы, цифры, `-`, `_`, метки по 1–63 байта, до 253, одна точка на
конце). HTTP CONNECT и абсолютные URL с кривым именем отвечают 400, SOCKS5
CONNECT — `0x01`, UDP-датаграммы SOCKS5/Shadowsocks отбрасываются, raw
не-ASCII (`bücher.de` по SOCKS5) отклоняется, а не переводится в punycode. В
mihomo такое имя проходило насквозь, минуя DOMAIN-правила.

## DNS

| Что | Статус | Подробности |
| :--- | :--- | :--- |
| `nameserver: system` | нет | Воспринимается как имя хоста. В mihomo это системный резолвер. Нужно указывать серверы явно (переменная `DNS_NAMESERVERS`) |
| DoQ, `nameserver: quic://` | нет | **Жесткая ошибка** загрузки. Заменяется на `tls://` или `https://` |
| `nameserver: sdns://` | нет | В mihomo — тихий warn-drop, здесь — **жесткая ошибка** |
| `default-nameserver` с **именем хоста** (`tls://dns.google`, `https://cloudflare-dns.com`, `udp://dns.google`, `dns.google`) | нет | **Жесткая ошибка загрузки**: `default-nameserver entry 'tls://dns.google:853#dns.google' must be a plain UDP/TCP nameserver (tls:// and https:// are not allowed here because they would create a bootstrap loop)`. Текст ошибки вводит в заблуждение — проверяется не транспорт, а наличие имени хоста: `udp://dns.google` отвергается с тем же сообщением. Bootstrap-серверы — только с IP-литералом |
| `default-nameserver` с **IP-литералом** (`tls://1.1.1.1`, `https://1.1.1.1`) | иначе | Принимается, но **транспорт и порт игнорируются**: запись используется как обычный plain-UDP-резолвер на порту 53 (то есть `tls://1.1.1.1` == `1.1.1.1`). Это не DoT/DoH, а тихая деградация — для bootstrap задавайте голый IP |
| Недоступный `default-nameserver` (IP-литерал без ответа) | нет | **Жесткая ошибка загрузки** с таймаутом 3 с: `cannot resolve 'dns.google' via bootstrap nameserver: query timed out after 3s`. Ядро падает на старте, а не переходит на резервный сервер |
| Зашифрованный upstream с именем хоста без `default-nameserver` | иначе | Ядро **не падает**: печатает предупреждение и поднимает bootstrap через системный резолвер (`/etc/resolv.conf`, при отсутствии — жёстко зашитые публичные серверы). Это рабочий, но неявный путь — задавайте `default-nameserver` явно |
| Запись `nameserver-policy`, у которой не осталось ни одного валидного URL | нет | В mihomo — паника во время выполнения, здесь — **жесткая ошибка** |
| Приоритет `nameserver-policy` | иначе | С 0.27 ключи применяются в **порядке документа** (паритет с mihomo): `rule-set:`/`geosite:`-ключ, записанный **до** доменного, затеняет его. Раньше любой доменный ключ молча выигрывал у любого матчера. Загрузка печатает предупреждение для каждой такой перевернутой пары |
| Шифрованный DNS через прокси (`?proxy=NAME`) | работает | С 0.27 `tls://dns.google?proxy=JP` и `https://...?proxy=JP` гоняют DoT/DoH-обмен через прокси; имя хоста такого upstream резолвится удаленно, локальный bootstrap не нужен. Работает в `nameserver`, `fallback`, `nameserver-policy` и `proxy-server-nameserver`; в `default-nameserver` прокси-спеллинги по-прежнему отвергаются |
| `#PROXY`-тег на зашифрованном upstream | иначе | В mihomo `tls://8.8.8.8#PROXY` значит «через прокси PROXY». Здесь `#` на `tls://`/`https://` — это **SNI**: конфиг грузится с предупреждением «did you mean `?proxy=X`?», но запрос уходит на SNI `PROXY`. Переписывайте на `?proxy=` |
| Plain-серверы с тегом `udp://host#PROXY` | работает | С 0.27 имя хоста резолвится **удаленно, через прокси** (паритет с mihomo `newDNSDialer`): локальный bootstrap больше не нужен, отравленный или неразрешимый локально адрес upstream не ломает загрузку |
| `fallback-filter` с гейтами GeoIP/IP-CIDR | иначе | Срабатывает не только при отказе основного сервера, но и на отравленных ответах (не-CN IP, bogon) |
| `fallback-filter.geoip: true` без MMDB | иначе | В mihomo — ошибка старта, здесь — предупреждение и **отключенный гейт** |
| `hosts` | иначе | Ключ находится на **верхнем уровне** конфига, а не внутри `dns:`. Карта `имя -> IP` (IP или список IP) плюс доменные алиасы; подстановочные знаки `*.corp.internal` и `+.corp.internal` работают, ключ с точкой на конце (`example.com.`) с 0.28 тоже срабатывает. Переключатель `dns.use-hosts` (по умолчанию `true`) управляет применением карты |
| `hosts` с некорректным значением | нет | **Жесткая ошибка** загрузки. Для одиночного значения: `hosts: value 'not-an-ip' for host 'example.com' is neither an IP address nor a valid domain alias` (одно значение может быть IP **или** доменным алиасом). Для списка: `hosts: invalid IP 'not-an-ip' for host 'example.com': invalid IP address syntax (lists may contain only IP addresses)` — в списке допустимы только IP |
| `hosts` внутри секции `dns:` | нет | Ключ там не существует: он **молча игнорируется**, без ошибки и без предупреждения. Ошибка в адресе внутри `dns.hosts` поэтому никогда не срабатывает — карта просто не применяется |
| `store-fake-ip` | иначе | Формат файла отличается от bbolt в mihomo. **Пути миграции между форматами нет** — при переносе база fake-ip пересобирается заново |
| `store-fake-ip: true` + `--config-string` | иначе | Файлы пишутся в resolved home dir, а не рядом с конфигом |
| Пул fake-ip | иначе | `.1` (шлюз), `.2`, `.3` (broadcast) зарезервированы, первый выдаваемый адрес — network + 4. Реальная емкость на 4 адреса меньше длины префикса |
| `fake-ip-range` только IPv4 при запросе AAAA | иначе | Отдается пустой NOERROR, клиент корректно откатывается на IPv4. За IPv6 fake-ip нужен IPv6-префикс в `fake-ip-range` |
| Неудачная привязка `dns.listen` или `external-controller` | нет | В mihomo демон продолжает работать, здесь процесс **падает с ненулевым кодом** |
| `dns.listen` при `dns.enable: false` | иначе | Предупреждение один раз |
| `nameserver-policy` с ключом `rule-set:` | частично | Работает для `domain`/`classical`; для `ipcidr` и при отсутствии провайдера — **жесткая ошибка** |

Поддерживается и работает как в mihomo: UDP/TCP-резолверы, DoH, DoT,
`default-nameserver` (с IP-литералом), `fallback-filter`, fake-ip с фильтрами и
режимами blacklist/whitelist, сброс кэша через `POST /cache/fakeip/flush`,
`dns.query` в API, тег `#PROXY` у plain-серверов, `?proxy=` у шифрованных и
`proxy-server-nameserver`.

## Правила маршрутизации

| Что | Статус | Подробности |
| :--- | :--- | :--- |
| `RULE-SET` внутри `AND` / `OR` / `NOT` | нет | Логические правила делегируют разбор, который ничего не знает о провайдерах: правило **предупреждается и отбрасывается**, трафик уходит мимо него. Составное `OR,((RULE-SET,a),(RULE-SET,b)),X` надо разворачивать в две последовательные строки |
| `GEOSITE` по файлу `.mrs` | работает | Формат MetaCubeX поддерживается |
| `GEOSITE` по файлу `.dat` | работает | С 0.26 поддерживается **оба** формата: `.mrs` и V2Ray `.dat` (protobuf). Ядро определяет формат по содержимому, а не по расширению |
| `GEOIP` по нестандартным категориям | нет | Работают только ISO-коды стран через `Country.mmdb`. Категории вида `akamai`, `amazon`, `fastly`, `oracle`, `cloudflare`, `google` (набор ZKEEN) не разрешаются: правило загружается, но **никогда не срабатывает** |
| `GEOSITE` по нестандартным категориям | иначе | В базе MetaCubeX категорий `domains`/`other`/`politic` нет — с ней правило грузится, но никогда не срабатывает. С 0.26 ядро читает V2Ray `.dat`, а с 0.27 — ключ `geox-url`: кастомная база (в шаблоне Stargate — ZKEEN, 34 КБ) делает категории рабочими. Категория должна существовать в загруженной базе — проверок нет, отсутствие — та же тихая ловушка |
| `IN-TYPE` с неизвестным значением | нет | В mihomo такое правило молча не срабатывает, здесь — **предупреждение и отбрасывание правила** (в `strict: true` — ошибка). Допустимы `HTTP`, `HTTPS`, `SOCKS5`, `TPROXY`, `INNER` |
| Доменные шаблоны вне явных правил (`fake-ip-filter`, `hosts`, `fallback-filter.domain`, домены в `.mrs`) | иначе | С 0.27 семантика как в mihomo: `x.com` — только сам домен, `*.x.com` — ровно одна метка ниже, `.x.com` — поддомены любой глубины, но не `x.com`, `+.x.com` — домен и все поддомены. Конфиги, которые при старой семантике «голый домен = домен с поддоменами», матчат меньше имен: пишите `+.example.com`. `nameserver-policy`-ключи с `*.`/`.` раньше никогда не срабатывали — теперь работают |
| «Мёртвые» доменные записи (`a..b`, точки по краям, `*`/`+` в payload `DOMAIN`, `+.x.com` в `DOMAIN-WILDCARD`, `..` в `DOMAIN-KEYWORD`) | иначе | С 0.29 такие записи при загрузке помечаются предупреждением с именем записи, в `strict: true` — **жесткая ошибка**. Затронуты `hosts:`, `nameserver-policy`, `fallback-filter.domain`, `fake-ip-filter`, `skip-domain`/`force-domain` сниффера и payload доменных правил: запись, которую нельзя сопоставить ни с одним нормализованным хостом, в mihomo хранилась молча. Совпадение помеченной записи не меняется — меняется только исход загрузки. `DOMAIN-REGEX` не проверяется вовсе |
| Имя входа `IN-NAME` для TUN | иначе | Всегда `meow-tun`, а не имя устройства |
| `sub-rules` с циклом или ссылкой на несуществующий блок | нет | **Жесткая ошибка** с указанием самого цикла |
| `SUB-RULE,<name>,<target>` с лишними полями | нет | **Жесткая ошибка**: `SUB-RULE` принимает ровно одно поле — имя блока |
| Обращение к процессу `PROCESS-NAME` | частично | Работает через netlink на Linux и libproc на macOS. На роутере выключайте (`FIND_PROCESS_MODE=off`) |
| `nameserver-policy` с ключом `geosite:` | частично | Работает при загруженной базе geosite; без базы запись пропускается с предупреждением |
| `IP-ASN` без базы ASN | нет | Правило отбрасывается с предупреждением: нужна `GeoLite2-ASN.mmdb` или `ASN.mmdb` |
| Счётчики совпадений правил (hit/miss) | нет | API `/rules` отдает `index`, `type`, `payload`, `proxy`, `size`, но **не** статистику совпадений — в mihomo есть обертки правил с hit-count |

Поддерживается полностью: `DOMAIN`, `DOMAIN-SUFFIX`, `DOMAIN-KEYWORD`, `IP-CIDR`,
`IP-CIDR6`, `GEOIP` (MaxMind MMDB), `GEOSITE` (mrs и dat), `RULE-SET` (mrs и YAML),
`SUB-RULE`, `AND`/`OR`/`NOT` (кроме `RULE-SET` внутри), `IN-NAME`, `IN-PORT`,
`IN-USER`, `SRC-GEOIP`, `SRC-IP-CIDR`, `NETWORK`, `DST-PORT`, `SRC-PORT`,
`MATCH`. Спец-прокси `PASS`, `PASS-RULE`, `COMPATIBLE`, `REJECT`,
`REJECT-DROP` встроены.

## Прокси-группы

### relay

Группы `select`, `url-test`, `fallback` и `load-balance` работают. Группа
`relay` работает с набором ограничений, из-за которых в этом репозитории
цепочки Chain построены на `dialer-proxy`, а не на relay.

| Что | Статус | Подробности |
| :--- | :--- | :--- |
| `use:` у группы relay | нет | Провайдеры не дают членов relay: группа **отбрасывается** с предупреждением («proxies list is empty»). Relay статичен: только явный список `proxies:` |
| `include-all`, `include-all-proxies`, `include-all-providers` у relay | нет | То же: группа отбрасывается, если из `proxies:` не набралось двух узлов |
| `filter` / `exclude-filter` у relay | нет | То же |
| `url`, `interval`, `lazy`, `tolerance`, `expected-status` у relay | нет | Предупреждение по каждому полю, цикл проверок не запускается |
| Собственная проверка живости | нет | Relay — фиксированная цепочка, а не пул. Для проверяемой цепочки relay оборачивают в `fallback` |
| Один прокси в `proxies` | нет | В mihomo — сквозной passthrough, здесь — группа **отбрасывается** с предупреждением (в `strict: true` — ошибка) |
| Пустой список `proxies` | нет | В mihomo — паника, здесь — группа **отбрасывается** с предупреждением |
| UDP через два и более прокси-звена | нет | `UdpNotSupported`, UDP-трафик пропускает правило, ведущее в эту группу. DIRECT-звенья не считаются: `[DIRECT, ss-b]` работает, `[ss-a, ss-b]` — нет |
| Цепочка из `hysteria2` | нет | QUIC/UDP не едет поверх TCP-потока, только как первое звено |
| `ss` с `gost-plugin`, `shadow-tls`, `restls`, `jls` или внешним SIP003-плагином | нет | Такой узел не может завершать цепочку: плагин владеет своим исходящим каналом |
| Мультиплексирование на звеньях relay | нет | Обходится: поток от relay одноразовый, повторно его не переоткрыть |

Перечисление группы-узла как звена relay разрешено: берется прокси, выбранный в
этой группе на момент соединения.

### Остальные типы

| Что | Статус | Подробности |
| :--- | :--- | :--- |
| Неизвестное значение `strategy` у `load-balance` | нет | В mihomo — тихий откат на round-robin, здесь — группа **отбрасывается** с предупреждением (в `strict: true` — ошибка). Допустимы `round-robin` и `consistent-hashing` |
| `strategy: consistent-hashing` | иначе | Ядро ведет себя как mihomo (ключ — адрес назначения, `jump_hash` по полному списку), но с фиксированным FNV-1a-64 вместо случайного зерна процесса. На практике это лучше: распределение не перетасовывается при каждом перезапуске |
| Все прокси мертвы | иначе | `NoProxyAvailable` сразу и явно, вместо выдачи мертвого узла и падения на соединении |
| `url`/`interval`/`lazy`/`tolerance`/`expected-status` у `select` | иначе | Предупреждение по каждому полю, цикл проверок не запускается. Mihomo с v1.18.4 обходит probe-циклом статические члены всех типов групп, meow-rs — нет |
| `icon` и `hidden` | работает | Начиная с 0.26 оба ключа разбираются и **отдаются в API** (`GET /proxies`) — панель может скрыть группу и показать иконку. На маршрутизацию они не влияют |
| Одинаковые имена групп | нет | **Жесткая ошибка** (в том числе совпадение с именем прокси или встроенным именем) |
| Циклические ссылки между группами | нет | **Жесткая ошибка** с указанием самого цикла (mihomo перечисляет только участников) |
| Одинаковые имена прокси | иначе | Более мягко, чем в mihomo: побеждает последнее объявление, ошибки нет |
| Сохранение выбора (`store-selected`) | иначе | Работает, но хранилище — JSON-файл, а не BoltDB `cache.db` из mihomo. Переносить базу выбора между ядрами нельзя |

## Провайдеры

### proxy-providers

| Что | Статус | Подробности |
| :--- | :--- | :--- |
| `type: inline` | нет | Неизвестный тип, провайдер пропускается. Поддерживаются только `http` и `file` |
| Наблюдение за файлом провайдера | иначе | Файл `type: file` перечитывается по `interval` (цикл обновления появился в 0.22). Без `interval` файл не перечитывается — нужен явный `interval` или `PUT /providers/proxies/{name}` |
| `path` вне рабочей папки | нет | Путь к файлу провайдера обязан оставаться внутри рабочей папки (containment). Отсюда техническое решение в `entrypoint.sh`: промежуточные файлы `srv.yaml` и `veth.yaml` пишутся в корень рабочей папки |
| Проверка живости у провайдера | частично | Блок `health-check:` **хранится, но по таймеру не опрашивается** — ядро печатает об этом предупреждение. Проверка идет только по ручному запросу `GET /providers/proxies/{name}/healthcheck` или силами собственных health-check групп (`url-test`/`fallback`/`load-balance`) |
| `override:` с `exclude-filter` / `exclude-type` | нет | Внутри `override:` учитывается **только** `dialer-proxy`. `exclude-filter` и `exclude-type` ставьте на уровне провайдера |
| `dialer-proxy` на узлах провайдера | частично | Работает начиная с 0.22 (issue #489): имя разрешается по живой карте маршрутов в момент соединения — статические прокси и группы, но не другие узлы провайдеров. Переприменяется при каждом обновлении провайдера. Цепочка, проходящая через динамический состав групп провайдера, ограничена 16 прыжками и падает: в Go есть растущий стек, в Rust — фиксированные кадры |
| Стабильность цепочки `dialer-proxy` | иначе | С 0.25 группа `url-test` держит исходящий на том члене, который последний его вел, и **пропускает членов, не способных достучаться до цепочки**. В mihomo такого поведения нет |
| `subscriptionInfo` провайдера | работает | С 0.26 HTTP-провайдер отдает в API расход трафика и срок из заголовка `subscription-userinfo` — так же, как mihomo. Знание хранится рядом с кэшем провайдера, поэтому переживает перезапуск |
| Загрузка подписки при старте | иначе | С 0.23 HTTP-провайдер **не блокирует старт**: конфиг грузится сразу, подписка докачивается в фоне. В mihomo провайдер тянется до старта ядра |
| Битый payload удаленного провайдера при `strict: true` | иначе | С 0.27 кривой payload от `http:`-провайдера, подписки или их кэша **не роняет старт** даже в `strict: true`: провайдер регистрируется пустым, ядро предупреждает и ретраит в фоне. Дефекты, написанные оператором (сам документ конфига, payload'ы `file:`/`inline:`), остаются фатальными |
| Проверка `file:`-провайдеров в `-t` | работает | С 0.27 `meow -t` читает и `file:`-провайдеры, так что проверка падает ровно там же, где упал бы старт; `PUT /configs` с новым битым `file:`-провайдером при `strict: true` отвечает 400 и ничего не применяет (`?force=true` применяет с пустым провайдером) |
| Битый payload удаленного rule-provider без `strict` | иначе | С 0.27 такой провайдер **остается зарегистрированным пустым** и ретраит, вместо того чтобы выпадать из конфига |

### rule-providers

| Что | Статус | Подробности |
| :--- | :--- | :--- |
| `interval` у файлового rule-provider | нет | Игнорируется с предупреждением, файл читается один раз. У `http`-провайдера `interval` работает |
| `interval` у `inline`-провайдера | нет | Провайдер не загрузится — поле нельзя указывать (в `strict: true` — ошибка) |

YAML с понятной ошибкой на бинарном мусоре. С 0.26 API отдает формат под
именами mihomo: `YamlRule`, `TextRule`, `MrsRule`.

## Геоданные

До 0.27 ядро скачивало все три базы при каждом старте безусловно; с 0.27
загрузка стала **reference-driven**: скачивается только то, на что конфиг
ссылается, и старый обходной путь с `/dev/null`-путями больше не нужен.

| Что | Статус | Подробности |
| :--- | :--- | :--- |
| Загрузка геобаз при старте | работает | Скачивается **только** то, что конфиг использует: правила `GEOIP`/`SRC-GEOIP`, `IP-ASN`/`SRC-IP-ASN`, `GEOSITE`, ключи `geosite:` в `nameserver-policy`, DNS fallback-фильтр с geoip-гейтом. Конфиг без ссылок не скачивает ничего |
| Путь скачивания | работает | Ключ `geodata.proxy` (с 0.27) называет прокси или группу, через которую качаются базы: `DIRECT`/`REJECT` как встроенные значения тоже работают. Без него — маршрут по умолчанию (последний `MATCH`), при неудаче — одна повторная попытка напрямую |
| `geox-url` (верхний уровень) | работает | С 0.27 читается как алиас `geodata.url.*` (явный блок `geodata.url` сильнее). Ключ `geoip` принимается и игнорируется с предупреждением: meow потребляет MMDB, а не `geoip.dat` |
| `geodata-mode`, `geodata-loader`, `geoip-matcher` | нет | Игнорируются с предупреждением |
| `geo-auto-update`, `geo-update-interval` | нет | Игнорируются. Используется секция `geodata:` |
| Имя файла geosite | иначе | По умолчанию `geosite.dat` (MetaCubeX больше не публикует `.mrs`), но загрузчик принимает оба формата |
| Имена файлов MMDB | иначе | С 0.26 ядро находит базу стран в любом регистре (`Country.mmdb`/`country.mmdb`) и принимает `ASN.mmdb` вместо `GeoLite2-ASN.mmdb` — так делают панели mihomo |
| Автообновление | частично | Тик `geodata.auto-update` обновляет только базы из startup-набора ссылок (ASN и geosite); `Country.mmdb` тиком никогда не обновляется — он скачивается, только если файла нет. Новый `PUT /configs`, добавивший `GEOIP`-правило, докачивает отсутствующую базу до применения |
| База, не скачавшаяся на старте | иначе | Referenced-geosite ретраится в фоне (с минуты до часа); GEOIP без базы — правило не срабатывает, ошибки загрузки нет |

Практическое следствие для meowkrotik: шаблон Full (`stargate.yaml`) ссылается
только на базу стран (единственное `GEOIP,RU`), поэтому тянет один
`Country.mmdb` — 7.3 МБ. Остальные пять шаблонов и `default_config.yaml` не
ссылаются на геоданные вовсе и ничего не скачивают (120–450 КБ на диске).
Прежний трюк с `mmdb-path: /dev/null` в них удален за ненадобностью: если
добавить в такой конфиг `GEOIP`- или `GEOSITE`-правило, база один раз скачается
в рабочую папку и правило заработает.

## Панель и REST API

| Что | Статус | Подробности |
| :--- | :--- | :--- |
| `external-ui-url` | нет | **Не скачивается** в релизной сборке. Возможность есть только под cargo-фичей `external-ui-download`, которая **выключена** по умолчанию. Встроенный дашборд meow-rs доступен всегда; стороннюю панель (zashboard, yacd) нужно распаковать в `$EXTERNAL_UI_PATH` самостоятельно |
| `external-ui` / `external-ui-name` | работает | Каталог статики раздается по `/ui` |
| `PUT /configs` | иначе | **Холодная перезагрузка:** соединения в полете обрываются и пишутся в лог. В mihomo — плавная передача |
| `PATCH /configs` | частично | С 0.26 поддерживает `mode`, `log-level` и **`tun`** — секция `tun` мержится поверх текущей (`enable`, `device`, `mtu`, `inet4-address`, `inet6-address`, `auto-route`, `outbound-interface`, `dns-hijack`, `udp-timeout`), слушатель TUN стартует, останавливается или перезапускается. Отличия от mihomo: отсутствие `enable` сохраняет текущее состояние (а не выключает TUN), а неудачный старт TUN отвечает 500. Порты, `allow-lan`, `bind-address`, `ipv6`, `sniffing`, `tcp-concurrent`, `find-process-mode`, `interface-name` не меняются |
| `PUT /configs` с сырым YAML вместо base64 | нет | Ответ 400 с понятным сообщением (в части версий mihomo принималось) |
| `GET /configs` | иначе | Возвращаются только непустые поля; mihomo отдавал полную структуру с `null`. С 0.26 дополнительно отдает состояние `tun` |
| Ключи `secret` не заданы | иначе | API остается открытым, ядро предупреждает при старте |
| Горячая замена обычных слушателей | нет | `PUT /configs` пересобирает прокси и правила, DNS и TUN, но **не** заменяет список `listeners:` на лету |
| UDP-сессии в `/connections` | нет | В таблице соединений только TCP-потоки |

Эндпоинты, которых в mihomo нет и которые добавлены в meow-rs (панели и
скрипты под них писать не нужно, они просто проигнорируются): `/metrics` в
формате Prometheus, `/api/subscriptions`, `/api/proxy-groups`, `/rules` с
CRUD-операциями, `/listeners`, `/statistics` (трафик по каждому прокси, с
0.24), `/logbook` (постоянный журнал событий в SQLite, с 0.25),
`GET /connections/{id}` с временной лентой заметок соединения (с 0.23; сами
заметки включаются ключом `connection-notes: true`, по умолчанию выключены).

Обратная сторона: эндпоинты mihomo, которые **не** реализованы, отвечают 404,
а не пустым успехом: `PATCH /rules/disable`, `POST /configs/geo`,
`GET/PUT/DELETE /storage/{key}`, `POST /restart`, `POST /upgrade*`.

## Что молча игнорируется, а что останавливает запуск

Отдельный раздел, потому что это самая неприятная категория: конфиг работал в
mihomo, а meow-rs на нем либо не стартует, либо стартует и тихо теряет часть
маршрутизации.

### Жёсткие ошибки (класс A) — конфиг не грузится

| Ошибка в конфиге | Поведение mihomo | Поведение meow-rs |
| :--- | :--- | :--- |
| Два слушателя на одном порту | последний молча перезаписывает первый | **ошибка загрузки** с именами обоих |
| Два слушателя с одинаковым именем | последний молча перезаписывает первый | **ошибка загрузки** |
| Неизвестный тип слушателя (`type: redir`, `type: tun`) | молча игнорируется | **ошибка загрузки** |
| Сокет-шорткат и запись `listeners:` на одном порту | принимаются оба | **ошибка загрузки** |
| Запись `authentication` без двоеточия (`userpass`) | сохраняется с пустым паролем | **ошибка загрузки** |
| Запись `authentication` с пустым именем (`:pass`) | принимается | **ошибка загрузки** |
| `skip-auth-prefixes` с некорректным CIDR | молча отбрасывается | **ошибка загрузки** |
| Некорректный IP в `hosts` (верхний уровень) | запись пропускается | **ошибка загрузки** |
| `nameserver-policy` без валидных серверов | паника во время выполнения | **ошибка загрузки** |
| `default-nameserver` с именем хоста (`tls://dns.google`, `udp://dns.google`) | принимается | **ошибка загрузки** (bootstrap не может разрешить сам себя). С IP-литералом (`tls://1.1.1.1`) принимается, но используется как plain UDP/53 |
| `dns.nameserver: quic://` или `sdns://` | работает или тихий warn-drop | **ошибка загрузки** |
| `tun.inet4-address` списком | принимается | **ошибка типа** |
| Цикл в `sub-rules` | паника или зацикливание | **ошибка загрузки** с указанием цикла |
| Ссылка `sub-rules` на несуществующий блок | молча не срабатывает | **ошибка загрузки** |
| `SUB-RULE` с лишними полями | принимается | **ошибка загрузки** |
| Одинаковые имена прокси-групп | принимаются | **ошибка загрузки** |
| Циклические ссылки между группами | перечисляет участников | **ошибка загрузки** с циклом |
| Дубликат ключа в YAML-маппинге | молча держит последнее значение | **ошибка разбора** (`duplicate mapping key: ...`), в том числе в подписках и payload'ах провайдеров |

### Молчаливые пропуски (класс B) — конфиг грузится, объект не работает

| Ошибка в конфиге | Поведение mihomo | Поведение meow-rs |
| :--- | :--- | :--- |
| `IN-TYPE` с неизвестным протоколом | молча не срабатывает никогда | правило **отбрасывается** с предупреждением |
| `RULE-SET` внутри `AND`/`OR`/`NOT` | работает | правило **отбрасывается** с предупреждением |
| `flow: xtls-rprx-direct` / `-splice` у VLESS | принимается, падает позже | узел **не разбирается** с предупреждением |
| `encryption` у VLESS кроме `none`/`mlkem768x25519plus...` | принимается | узел **не разбирается** с предупреждением |
| Vision у VLESS поверх ws/grpc/h2 | грузится, падает на соединении | узел **не разбирается** с предупреждением |
| Неизвестный `strategy` у `load-balance` | тихий откат на round-robin | группа **отбрасывается** с предупреждением |
| Relay с одним прокси | сквозной passthrough | группа **отбрасывается** с предупреждением |
| Relay с `use:`/`include-all*` | работает | группа **отбрасывается** с предупреждением |
| `interval` у `inline`-rule-provider | ошибка провайдера | провайдер **не грузится** (в `strict: true` — ошибка загрузки) |
| `interval` у файлового rule-provider | работает | игнорируется с предупреждением |
| `sniffer.sniff.QUIC` | работает | ключ **отбрасывается** с предупреждением |
| `sniffer.force-dns-mapping` | влияет на поведение | принимается и **игнорируется** с предупреждением |
| `hosts` внутри секции `dns:` | работает | **молча игнорируется**, без предупреждения |
| `interface-name`/`ip-version`/`routing-mark` у узла `direct` | привязывают трафик | **молча игнорируются** |
| `external-ui-url` | панель скачивается | URL запоминается, но **не скачивается** |
| `geodata-mode`, `geodata-loader`, `geoip-matcher`, `geo-auto-update`, `geo-update-interval` | работают | **игнорируются** с предупреждением (`geox-url` с 0.27 читается — см. раздел «Геоданные») |
| Числоподобный `password: 000000` без кавычек у узла | держит строкой | узел **отбрасывается** с предупреждением `missing password` (в `strict: true` — ошибка) |
| Блок `iptables:` верхнего уровня | работает | **молча игнорируется**, без предупреждения |
| Поля TUN `stack`, `strict-route`, `auto-redirect`, `auto-detect-interface`, `endpoint-independent-nat`, `mtu-v6`, `route-address`, `route-exclude-address`, `include-uid`, `exclude-uid` | работают | **игнорируются** с предупреждением (`tun.<поле>: field is not supported in meow-rs and will be ignored`) |
| `nameserver: system` | системный резолвер | воспринимается как **имя хоста** |
| `find-process-mode` | включает/выключает поиск процесса | **молча игнорируется**: поиск процесса запускается сам, только когда в правилах есть `PROCESS-NAME` |
| `keep-alive-idle` / `keep-alive-interval` / `disable-keep-alive` | настраивают keepalive входящих **и исходящих** | ключи **игнорируются с предупреждением** и подсказкой про `tcp-keepalive-*`. С 0.29 входящие сокеты настраиваются своими ключами `tcp-keepalive*`, а у исходящих dial'ов настраиваемого keepalive нет вовсе (остаточная разница с mihomo). Из шаблонов репозитория ключи убраны, чтобы не сыпать предупреждениями |

Ключ `strict: true` переводит пропуски второй таблицы в ошибки загрузки. Если
конфиг готовится вручную и важно, чтобы ничего не выпало молча, включайте его
на этапе проверки: `docker run --rm <образ> -t` с добавленным `strict: true`.

Перед переносом любого конфига имеет смысл прогнать проверку:
`docker run --rm ghcr.io/viktor45/meowkrotik:latest -t` (в RouterOS —
`cmd="-t"`). Сообщение об ошибке указывает поле и причину.

## Сводный список: от чего придется отказаться

Короткий перечень для тех, кто переходит с mihomo:

1. **Подписки не в Clash YAML** (URI-список, base64) — нужен Clash-формат.
2. **Локальные прокси как URI** — переписать все `SRV<n>` в однострочный YAML.
3. **Протоколы TUIC, WireGuard, SSH, ShadowsocksR** — узлы такого типа
   вылетят из подписки, их надо заменить или удалить.
4. **TrustTunnel** — в релизной сборке нет, нужен свой бинарник с cargo-фичей.
5. **Snell v1/v2** — только v3–v6.
6. **`flow: xtls-rprx-direct` и `-splice`** — только `xtls-rprx-vision`, и только
   на `network: tcp` с TLS или REALITY.
7. **TUN как `listeners: - type: tun`** — переписать в секцию `tun:` верхнего
   уровня, `inet4-address` сделать строкой, а в правилах `IN-NAME` заменить имя
   на `meow-tun`. Учесть: транзитный трафик без fake-ip в устройство не
   попадает (свой трафик хоста с `auto-route: true` перехватывается целиком).
8. **`TUN_STACK`, `TUN_AUTO_ROUTE` и прочие mihomo-поля TUN** — в части случаев
   просто игнорируются.
9. **UDP через tproxy без внешних правил** — `udp: true` требует
    `firewall: false`; правила TPROXY для UDP ставит entrypoint через nft.
10. **`redir-port`** — только `tproxy-port`.
11. **Внешний блок `iptables:`** — игнорируется; логика переносится на
    `firewall:` записи tproxy, и по умолчанию теперь **включена**.
12. **`nameserver: system`** — резолверы задаются явно.
13. **DoQ (`quic://`) и `sdns://` в DNS** — заменить на `tls://`/`https://`.
14. **`default-nameserver` с именем хоста** — только IP-литерал; `tls://1.1.1.1`
    принимается, но используется как обычный plain-UDP/53.
15. **`hosts` внутри секции `dns:`** — перенести на верхний уровень конфига.
16. **`RULE-SET` внутри `AND`/`OR`/`NOT`** — развернуть в последовательные
    правила, иначе они молча отбросятся.
17. **GEOIP по нестандартным категориям** (ZKEEN: akamai, amazon, fastly,
    oracle, cloudflare, google) — правило загрузится, но никогда не сработает;
    заменить на ipcidr- rule-providers.
18. **GEOSITE по нестандартным категориям** с базой MetaCubeX — таких
    категорий там нет; нужна кастомная база через `geox-url` (в шаблоне
    Stargate — ZKEEN `domains`/`other`/`politic`).
19. **`use:`, `include-all*`, `filter` в группе `relay`** — только явный список
    `proxies:` из двух и более узлов.
20. **Проверка живости внутри `relay`** — обернуть relay в `fallback` или
    использовать `dialer-proxy`.
21. **Цепочки через `relay` для UDP** — работает только при одном прокси-звене
    (плюс DIRECT).
22. **`hysteria2` внутри TCP-цепочки** — только первым звеном.
23. **Файл провайдера без `interval`** — правки файла не подхватываются, нужен
    `interval` или ручной `PUT /providers/proxies/{name}`.
24. **`interval` у файлового или `inline`-rule-provider** — не работает /
    ломает загрузку.
25. **`exclude-filter`/`exclude-type` внутри `override:`** — только `dialer-proxy`
    учитывается; фильтры ставятся на уровне провайдера.
26. **`path` провайдера вне рабочей папки** — файл должен лежать внутри нее.
27. **Автоскачивание панели через `external-ui-url`** — распаковать вручную.
28. **Плавный перезапуск через `PUT /configs`** — соединения обрываются.
29. **Горячая замена слушателей** — `PUT /configs` их не пересоздает.
30. **Сниффер QUIC** — ключ убрать; только TLS и HTTP.
31. **`force-dns-mapping`** — игнорируется.
32. **База fake-ip** — формат хранения несовместим с mihomo, миграции нет.
33. **База выбора групп** (`store-selected`) — JSON вместо BoltDB, переносить
    выбор между ядрами нельзя.
34. **Счетчики совпадений правил** — в `/rules` их нет.
35. **UDP-сессии в таблице соединений** — их нет.
36. **Multi-WAN через VETH** — поля `interface-name`, `ip-version` и
    `routing-mark` у узла `direct` не реализованы; работает только
    верхнеуровневый `routing-mark`.
37. **Числоподобный `password` без кавычек** в узлах подписки
    (`password: 000000`) — узел отбрасывается с предупреждением; кавычки
    ставит панель или правится узел вручную.
38. **Дубликаты ключей в YAML** — теперь жёсткая ошибка разбора, а не
    «последний выигрывает».

Плюс изменения поведения без полной несовместимости: `select` и `relay` не
запускают цикл проверки живости; health-check провайдера хранится, но по
таймеру не опрашивается; DNS-фильтр по GeoIP отключается вместо падения, если
нет MMDB; HTTP-провайдеры докачиваются в фоне, не блокируя старт; доменные
шаблоны вне явных правил матчат по семантике mihomo (`x.com` — только сам
домен); `nameserver-policy` применяется в порядке документа; цепочки
merge-ключей теперь раскрываются; «мёртвые» доменные записи (пустые метки,
точки по краям, `*`/`+` в payload `DOMAIN`) с 0.29 предупреждаются, а в
`strict: true` останавливают загрузку.

## Что придется поправить при переносе готового конфига mihomo

Порядок разумной проверки:

1. Заменить `TUN`-блок на секцию `tun:` верхнего уровня; `inet4-address`
   превратить в строку; в правилах `IN-NAME` оставить `meow-tun` (и `tun-in`
   для tproxy, `mixed-in` для mixed).
2. Убрать из DNS `system` и любые `quic://`; `hosts` (если есть) перенести из
   `dns:` на верхний уровень. В `default-nameserver` оставить только IP-литералы.
3. Прогнать `-t` и читать ошибки до конца — они перечисляют проблемные поля.
4. Проверить каждый тип прокси в подписке: `tuic`, `wireguard`, `ssh`, `ssr`,
   `trusttunnel` надо заменить или вырезать; узлы с числоподобным паролем
   без кавычек ядро отбросит — их тоже надо починить.
5. Развернуть составные логические правила в последовательные.
6. Пересобрать списки правил: нестандартные категории GEOIP и GEOSITE — в
   ipcidr- и доменные провайдеры.
7. Проверить, что у каждого file-провайдера стоит `interval`, а `path` внутри
   рабочей папки.
8. Если используется `relay` — проверить, что в нем явный список из двух и
   более узлов и нет `use:`/`filter`.
9. Добавить `strict: true` и прогнать `-t` еще раз — так выявятся все
   тихие пропуски, а не только те, что бьют по загрузке.

## Ограничения самого контейнера meowkrotik

Это не ограничения ядра, но они тоже означают отказ от привычного.

- **Панель не ставится автоматически.** `EXTERNAL_UI_URL` запоминается, но ядро
  ничего не скачивает. Более того, `entrypoint.sh` удаляет папку панели целиком
  при **любом** изменении `EXTERNAL_UI_URL`, включая сброс в пустое значение:
  перед сменой переменной панель нужно распаковать заново.
- **Нужен хотя бы один источник прокси.** Без единого `SUB<n>` и ни одного
  `SRV<n>` секция `proxy-providers` остается пустой, и ядро отказывается
  принимать конфиг. `entrypoint.sh` предупреждает об этом заранее.
- **Конфиг пересобирается на каждом старте.** Правка шаблона не подхватывается на
  лету: после любого изменения нужен перезапуск контейнера. `envsubst`
  подставляет переменные только на старте, так что после правки `envs` в
  RouterOS тоже нужен рестарт.
- **Пустая переменная заменяется пустой строкой.** Каждая `$VARIABLE` в шаблоне
  должна иметь значение по умолчанию в `Dockerfile` либо выставляться
  скриптом, иначе `envsubst` вырежет подстановку.
- **`arm/v7` теперь тоже скачивается.** С релиза meow-rs v0.29.0 апстрим публикует
  статический musl-бинарник под 32-битный ARM, и все три архитектуры образа
  собираются одинаково — скачиванием готового релиза; компиляции в Dockerfile
  больше нет. (Раньше arm/v7 собирался из исходников: единственный armv7-релиз
  был динамическим и не запускался в Alpine без GLIBC_2.28.)
- **Журналы ядра выключены в шаблонах.** Ядро ведет два SQLite-хранилища в
  рабочей папке, оба — по умолчанию включенные: журнал событий
  (`logbook/logbook.db`, с 0.25 — обновления провайдеров и прочие события,
  ядро ограничивает его 2 МБ и 7 сутками) и журнал трафика
  (`traffic/traffic.db`, с 0.29 — поминутный учет по хостам за 62 дня, сброс
  на диск каждые 60 секунд; данные отдаются через `GET /traffic/ledger`).
  Оба — постоянная запись на флеш-накопитель роутера, поэтому все шаблоны и
  `default_config.yaml` задают `logbook: {enable: false}` и
  `traffic-ledger: {enable: false}`: `GET /logbook` и `GET /traffic/ledger`
  отвечают `enabled: false`, история в панели недоступна, зато диск в простое
  не пишется вовсе. Вернуть можно, убрав секцию (или поставив
  `enable: true`).
- **Журнал трафика выключен в шаблонах** — см. пункт про журналы ядра выше.
- **`ui`-панель и API на одном порту.** Это совпадает с mihomo, ничего нового.

## Что ограничением не является

Чтобы не искать лишнего, список того, что в mihomo было и **в meow-rs работает**:

- все основные порты и режимы (`mixed-port`, `socks-port`, `port`,
  `allow-lan`, `bind-address`, `mode: rule/global/direct`);
- REST API и встроенная панель, `secret` как Bearer, `external-controller`;
- авторизация входящих (`authentication`, `skip-auth-prefixes`) — при этом
  loopback (`127.0.0.1/32`, `::1/128`) всегда пропускается независимо от конфига,
  а неверная запись `authentication` дает ошибку вместо тихого поведения;
- именованные слушатели `listeners:` и правила `IN-NAME`/`IN-TYPE`/`IN-PORT`/
  `IN-USER`;
- Shadowsocks, Trojan, VMess, VLESS (включая Reality/uTLS и постквантовую
  схему), Hysteria2 (включая obfs: gecko, с 0.27), Snell v3–v6, AnyTLS, HTTP,
  SOCKS5 (включая UDP через `udp: true`), direct, reject;
- входящий Shadowsocks (`listeners: - type: shadowsocks`) — с 0.27 в релизной
  `full`-сборке;
- группы `select`, `url-test`, `fallback`, `load-balance` (`round-robin` и
  `consistent-hashing`) и `relay` для TCP; фильтры групп `filter`,
  `exclude-filter` и `exclude-type` (в том числе на провайдерах);
- `filter`/`exclude-filter`, `include-all`, `max-failed-times`, `tolerance`,
  прокси- и rule-провайдеры типов `http`, `file` и `inline` (у `inline` — без
  `interval`);
- `dialer-proxy` и `override.dialer-proxy`, в том числе на провайдерах, — на
  этом построены цепочки шаблона Chain;
- `icon` и `hidden` у групп — разбираются и отдаются в API (с 0.26);
- DNS: UDP/TCP, DoH, DoT, `default-nameserver` (с IP-литералом), `nameserver-policy`,
  `fallback-filter`, `hosts` на верхнем уровне (включая подстановочные знаки),
  fake-ip v4/v6 с фильтрами и режимами blacklist/whitelist, сохранение базы
  fake-ip, `#PROXY`-теги у plain-серверов, `?proxy=` у шифрованных (с 0.27),
  `proxy-server-nameserver` и `direct-nameserver` с
  `direct-nameserver-follow-policy` (с 0.29 — паритет с mihomo: DIRECT-исходящие
  резолвят имя через отдельный сервер);
- keepalive входящих сокетов: с 0.29 ядро ставит `SO_KEEPALIVE` на каждый
  принятый TCP-сокет инбаундов (`tcp-keepalive`, `tcp-keepalive-idle`,
  `tcp-keepalive-interval`, `tcp-keepalive-probes` — по умолчанию 300/30/5) и
  умеет рвать релеи, молчаливые в обе стороны, опциональным `tcp-idle-timeout`
  (выключен по умолчанию). Это meow-расширение: mihomo-ключи
  `keep-alive-idle`/`keep-alive-interval` принимаются, но игнорируются — они
  там настраивали и исходящие тоже;
- журналы ядра: событий (`GET /logbook`, с 0.25) и трафика (`GET /traffic/ledger`,
  с 0.29 — поминутный учет по хостам, приложениям, политике и интерфейсу за
  62 дня). Ядро ведет оба по умолчанию, но в шаблонах этого репозитория они
  выключены из-за записи на флеш (см. раздел про контейнер);
- правила `DOMAIN`, `DOMAIN-SUFFIX`, `DOMAIN-KEYWORD`, `IP-CIDR`, `IP-CIDR6`,
  `GEOIP`, `GEOSITE` (и `.mrs`, и `.dat`), `RULE-SET`, `SUB-RULE`, `AND`/`OR`/`NOT`,
  `PROCESS-NAME`, `MATCH`;
- спец-прокси `PASS`, `PASS-RULE`, `COMPATIBLE`, `REJECT`, `REJECT-DROP`;
- секция `geodata:` с настройкой путей, автообновления и интервала;
- `PUT /configs`, `PATCH /configs` (включая переключение TUN), `GET /configs`,
  `/metrics` в формате Prometheus, `/statistics` с трафиком по каждому прокси,
  `subscriptionInfo` у провайдеров, `provider-name` у прокси;
- CLI-флаги `-t`, `-d`, `-f`, `-v` — совместимы с mihomo.
