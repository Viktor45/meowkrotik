# Шаблоны конфигурации meow-rs для MikroTik

Готовые конфигурационные шаблоны для развертывания контейнера [meow-rs](README.md) на маршрутизаторах MikroTik — drop-in замена контейнера [wiktorbgu/mihomo-mikrotik](https://hub.docker.com/r/wiktorbgu/mihomo-mikrotik) с той же моделью шаблонов и переменных окружения. Развертывание контейнера описано в [README.md](README.md), здесь — только сами шаблоны.

Шаблоны приведены в иллюстративных целях, содержат комментарии и позволяют построить конфигурацию под ваши персональные нужды. Не стесняйтесь их редактировать, убирать лишнее и присылать PR, если придумали улучшение или вариант шаблона, который подойдет и остальным пользователям. Шаблоны распространяются по лицензии [MIT](LICENSE).

## Быстрый старт

### 1. Загрузите файл шаблона

Выберите подходящий вам файл из таблицы ниже и скопируйте его на роутер через **SFTP** в папку:

```
/usb1/docker_configs/meowkrotik/template/
```

Если к шаблону прилагается .sh-файл, положите его в папку для скриптов **user_sh**:

```
/usb1/docker_configs/meowkrotik/user_sh/
```

Путь может отличаться, если вы меняли настройки по умолчанию и у вас контейнер расположен в другом хранилище.

<details>
<summary><b>Альтернатива без SFTP - скачать прямо на роутере через /tool fetch</b></summary>

Вместо SFTP файл можно скачать на роутер прямо из интернета командой `/tool fetch` (в терминале RouterOS). Параметр `dst-path` задает путь сохранения - укажите его **полностью, вместе с именем файла**:

```bash
# Шаблон Lite
/tool fetch url="https://raw.githubusercontent.com/Viktor45/meowkrotik/refs/heads/main/templates/stargate-lite.yaml" dst-path="/usb1/docker_configs/meowkrotik/template/stargate-lite.yaml"

# Шаблон Area (два файла)
/tool fetch url="https://raw.githubusercontent.com/Viktor45/meowkrotik/refs/heads/main/templates/area/stargate-area.yaml" dst-path="/usb1/docker_configs/meowkrotik/template/stargate-area.yaml"
/tool fetch url="https://raw.githubusercontent.com/Viktor45/meowkrotik/refs/heads/main/templates/area/user_sh/stargate-area.sh" dst-path="/usb1/docker_configs/meowkrotik/user_sh/stargate-area.sh"

# Шаблон Chain (два файла)
/tool fetch url="https://raw.githubusercontent.com/Viktor45/meowkrotik/refs/heads/main/templates/chain/stargate-chain.yaml" dst-path="/usb1/docker_configs/meowkrotik/template/stargate-chain.yaml"
/tool fetch url="https://raw.githubusercontent.com/Viktor45/meowkrotik/refs/heads/main/templates/chain/user_sh/stargate-chain.sh" dst-path="/usb1/docker_configs/meowkrotik/user_sh/stargate-chain.sh"
```

Ссылки для остальных шаблонов - в колонке «Скачать» таблицы выше.

### 2. Активируйте шаблон

Установите окружение (ENV) контейнера на загруженный шаблон через параметр (key) CONFIG набора параметров (Mihomo). В команде ниже замените `имя-шаблона.yaml` на выбранный файл (например, `stargate-lite.yaml`):

```bash
/container envs add list=MEOW key=CONFIG value="имя-шаблона.yaml"
```

**⚠️ Важно:** `envs add` создает **новую** переменную. Если `CONFIG` в списке `MEOW` уже существует (например, при смене шаблона или списка стран), сначала удалите старое значение и затем добавьте новое:

```bash
# Посмотреть существующие переменные
/container envs print

# Удалить старое значение CONFIG (номер из print)
/container envs remove numbers=0

# Добавить новое
/container envs add list=MEOW key=CONFIG value="новое-значение"
```

Либо отредактируйте значение переменной в Winbox: **Container → EnvLists → MEOW**.

### 3. Перезапустите контейнер

Перезапуск нужен для применения шаблона - в том числе после его обновления или редактирования.

```bash
/container stop [find name="meow"]
/container start [find name="meow"]
```

Имя контейнера (`meow`) задавалось при установке, см. [README](README.md#установка-контейнера).

### Шаблоны из двух файлов (Area, Chain)

Шаблоны **Area** и **Chain** состоят из двух файлов: YAML-шаблона и `.sh`-скрипта. Без скрипта шаблон загрузится, но групп не будет: Area не создаст `XX_*` переключатели по странам, Chain не создаст цепочки `VIA_RU_*`.

1. Положите оба файла (через SFTP или `/tool fetch`):

   | Шаблон | Файл в `template/` | Файл в `user_sh/` |
   | :--- | :--- | :--- |
   | Area  | [stargate-area.yaml](templates/area/stargate-area.yaml)  | [stargate-area.sh](templates/area/user_sh/stargate-area.sh)  |
   | Chain | [stargate-chain.yaml](templates/chain/stargate-chain.yaml) | [stargate-chain.sh](templates/chain/user_sh/stargate-chain.sh) |

2. Задайте `CONFIG` и, для Area, список стран:

   ```bash
   /container envs add list=MEOW key=CONFIG value="stargate-area.yaml"
   /container envs add list=MEOW key=SG_COUNTRIES value="US,NL,DE"
   ```

3. Перезапустите контейнер — скрипты выполняются только при старте.

### Обновление шаблона до новой версии

Шаблоны в этом репозитории периодически обновляются. Чтобы перейти на новую версию:

1. **Сохраните свои правки** (если делали их): вручную выбранные прокси в панелях хранятся в кеше ядра отдельно от шаблона (при включенном `STORE_SELECTED`), а вот правки текста самого шаблона при перезаписи файла будут потеряны - перенесите их в новый файл заранее.
2. Скачайте новый файл тем же способом (SFTP с заменой или `/tool fetch` с тем же `dst-path` - старый файл будет перезаписан).
3. Перезапустите контейнер:
   ```bash
   /container stop [find name="meow"]
   /container start [find name="meow"]
   ```

Проверьте после запуска, что все группы появились в панели. Если добавились новые переменные окружения - значения для них берутся из списка `MEOW` (см. таблицы ниже).

### Диагностика проблем

Если контейнер не стартует или прокси не работают:

1. **Включите логирование контейнера**, чтобы вывод ядра попадал в журнал RouterOS:
   ```bash
   /container set [find name="meow"] logging=yes
   ```
   Читайте лог через `/log print` (или Winbox → Log).
2. **Проверьте, что CONFIG указывает на существующий файл.** При опечатке в имени в логе будет `ERROR: Config not found! Checked: ...template/имя.yaml and .../имя.yaml` - проверьте имя переменной и что файл лежит в папке `template`.
3. **Проверьте, что .sh-скрипт лежит в user_sh.** Шаблоны Area и Chain без своего скрипта не сгенерируют группы по странам/цепочки: в панели не появятся `XX_*`/`VIA_RU_*` переключатели. Убедиться можно по строке `Running user scripts: /etc/mihomo/user_sh/...` в логе.
   Для Area отдельно проверьте `SG_COUNTRIES`: если переменная не задана, скрипт пишет `SG_COUNTRIES not set, skipping area groups generation` и выдаёт пустой набор групп.
4. **Ошибка парсинга шаблона** - ядро пишет отладочный файл рядом с рабочей директорией контейнера (см. [документацию контейнера](https://hub.docker.com/r/wiktorbgu/mihomo-mikrotik)); сам файл лога удобно посмотреть через SFTP.
5. **Переменные подставляются только при старте.** После изменения любой переменной (`SG_COUNTRIES`, `SUB1`, ...) нужен перезапуск контейнера - одного обновления подписок недостаточно.
6. **Нет ни одной подписки.** Без `SUB<n>` и `SRV<n>` секция `proxy-providers` остаётся пустой, и ядро отказывается принимать конфиг с `invalid type: map, expected a sequence`. Перед этим `entrypoint.sh` пишет `WARNING: no SUB*/SRV* variables set`.
7. **Правило молчит.** Если группа в панели есть, а трафик через неё не идёт, посмотрите в логе предупреждения `rule-provider ... payload unavailable`: список правил не скачался (404 или нет сети) и был подставлен пустым.
8. Распространенная причина «не работает» - BOM-кодировка файла после редактирования: сохраняйте шаблон в **UTF-8 без BOM** (подробнее в разделе «Кодировка» ниже).

## Описание шаблонов

Шаблоны можно сразу использовать, но, возможно, они содержат избыточный код, который вам может не потребоваться. При необходимости редактируйте их согласно [официальному примеру](https://github.com/MetaCubeX/mihomo/blob/Meta/docs/config.yaml) и [документации](https://wiki.metacubex.one/ru/config/general/). Поскольку это файлы ШАБЛОНОВ конфигурации, а не сами конфигурации, они содержат переменные со знаком `$` и могут не поддерживаться вашим YAML-редактором.

### Потребление ресурсов (измерено)

Все значения сняты с одного и того же контейнера, поэтому сравнивать их можно напрямую. Условия замера:

- Ядро: meow-rs v0.22.0, образ `linux/amd64` (Docker Desktop на macOS)
- Подписки: 1 штука по HTTP, 30 прокси в ней; дополнительно `SRV1` с одним локальным прокси
- Замер снимается через 75 секунд после загрузки конфига, когда подтянуты провайдеры и списки правил
- Память: `VmHWM` (пик с момента старта) и `VmRSS` (в момент замера) процесса `mihomo` из `/proc/<pid>/status`
- Место: `du` рабочей папки контейнера после загрузки всех файлов

| `default_config.yaml` |   16.8 МБ  |           11.2 МБ   |     13 / 5      |     24 КБ   |             -   |       -   |

Что из этого видно:

- **Место почти везде ничтожно.** Кроме Full все шаблоны укладываются в 200 КБ. Full раздувают геобазы: 22.9 МБ из 24.0 МБ приходится на `Country.mmdb`, `GeoLite2-ASN.mmdb` и `geosite.dat`.
- **Пик памяти у Full втрое выше остальных** ровно из-за этих баз. Если маршрутизатор не тянет 40 МБ в момент старта, Full на нём не заработает, хотя в простое держится всего 11 МБ.
- **Порядок шаблонов по пику** совпадает с их сложностью: Nano → Lite/Mini → Area/Chain → Full.
- **Память после старта и пик — разные вещи.** У Mini пик 11.5 МБ, а в простое 8.3 МБ; у Chain пик 17.7 МБ, в простое 4.1 МБ. Для оценки «влезет ли в роутер» смотрите на пик.
- Значения для Area и Chain зависят от нагрузки: здесь 3 страны, у Area с 15 странами групп будет в разы больше.

Это замер на `linux/amd64`. На 32-битном ARM (`arm/v7`) и на `arm64` цифры будут другими, а объём геобаз на Full останется тем же, потому что файлы одни и те же.

### Конфиг по умолчанию (default_config.yaml)

Кроме шести шаблонов в образе есть `default_config.yaml` — он запускается, когда переменная `CONFIG` равна `default_config.yaml` (такое значение стоит в образе по умолчанию), то есть это состояние контейнера «из коробки», без загруженных файлов. ⚠️ Если задать `CONFIG` пустой строкой, дефолтный конфиг **не** подставится: поиск файла не найдёт и контейнер завершится с `ERROR: Config not found!` Шаблон лежит в образе по пути `/etc/mihomo/template/default_config.yaml`, а `entrypoint.sh` при каждом старте сверяет его с копией в рабочей папке: если файл отличается, старая версия уезжает в `default_config_old.yaml`, и свежая копия кладётся на место. Правки вашего конфига при этом не теряются, пока вы не переименуете свой файл.

Что в нём есть: mixed-вход на 1080, REST API и встроенная панель на 9090, DNS-резолвер, группы `SELECTOR`, `AUTO`, `FALLBACK`, `MANUAL`, `LOADBALANCE`, `QUIC UDP 443`, обработка QUIC, входы TUN/tproxy/mixed и подписки из `SUB*`/`SRV*`. Чего нет: никаких сервисных групп, правил по странам, цепочек, rule-providers и геоданных.

По замеру это самый дешёвый конфиг по месту (24 КБ) и по числу правил (5), но пик памяти у него 16.8 МБ — почти как у Area. Причина в том, что ядро при старте всё равно готовит TUN, fake-ip и DNS независимо от числа правил, и на коротком участке поднимает память. В простое держится 11.2 МБ.

Если шаблон Stargate не подходит, начните с этого конфига: он работает сразу после установки и служит хорошим черновиком, в который можно переносить блоки из шаблонов.

### Страны (Area)

Шаблон с динамическими переключателями по странам. Позволяет гибко управлять трафиком через прокси конкретных стран, аналогично тому, как работают RU_* группы для России.

Чтобы шаблон работал правильно, необходимо в контейнер положить ДВА файла, из которых он состоит.

  - Файл шаблона: [stargate-area.yaml](templates/area/stargate-area.yaml)
  - Скрипт: [stargate-area.sh](templates/area/user_sh/stargate-area.sh)

**Как это работает:**

Вы задаете список нужных стран через одну переменную окружения `SG_COUNTRIES`, а скрипт автоматически создает для каждой страны до 5 переключателей.
Страна RU (🇷🇺) всегда присутствует:

```
SG_COUNTRIES="US,NL,DE,GB,FR,JP,SG"
```

```bash
/container envs add list=MEOW key=SG_COUNTRIES value="US,NL,DE,GB,FR,JP,SG"
```

**Режим фильтрации прокси (SG_CODE):**

По умолчанию скрипт фильтрует прокси **только по флагу эмодзи** страны (🇺🇸, 🇩🇪 и т.д.). Если ваши прокси не содержат флаги в названиях, но содержат коды стран в верхнем регистре (US, DE, NL), установите `SG_CODE="true"`, чтобы фильтр искал и по флагу, и по коду одновременно.

| Значение `SG_CODE`     | Фильтр для US | Когда использовать                                              |
| :--------------------- | :------------ | :-------------------------------------------------------------- |
| `false` (по умолчанию) | `(?i)🇺🇸`       | Прокси содержат флаг эмодзи в названии: `🇺🇸 US Server 1`         |
| `true`                 | `(?i)🇺🇸\|US`   | Прокси содержат и флаг, и код: ищет совпадение по любому из них |

```bash
# Только по флагу (по умолчанию, обычно флаг страны всегда присутствует в подписках)
/container envs add list=MEOW key=SG_CODE value="false"

# По флагу И коду страны (могут быть пересечения стран, если они называются полными латинскими названиями)
/container envs add list=MEOW key=SG_CODE value="true"
```

**💡 Совет:** Если ваши прокси в подписках **не содержат эмодзи флагов** в названиях, установите `SG_CODE="true"` - тогда фильтр будет искать прокси по коду страны (US, DE, NL) даже без флага.

Для каждой страны создаются группы:
- `XX_AUTO` - автоматический выбор (FASTEST → FAILOVER → AUTO)
- `XX_MANUAL` - ручной выбор прокси страны
- `XX_FASTEST` - самый быстрый прокси страны (url-test)
- `XX_FAILOVER` - резервный прокси страны (fallback)
- `XX_LOADBALANCE` - распределение нагрузки прокси страны (loadbalance)

Чтобы включить или выключить отображение `XX_FASTEST`, `XX_FAILOVER` и `XX_LOADBALANCE` для генерируемых стран (по умолчанию включено)
в целях экономии памяти и ресурсов установите переменным окружения `SG_FASTEST`, `SG_FAILOVER` и `SG_LOADBALANCE` значение `true` или `false`.

| Переменная       | Значение | Результат                          |
| :--------------- | :------- | :--------------------------------- |
| `SG_FASTEST`     | `true`   | Поиск быстрого - включен           |
| `SG_FASTEST`     | `false`  | Поиск быстрого - выключен          |
| `SG_FAILOVER`    | `true`   | Поиск доступного - включен         |
| `SG_FAILOVER`    | `false`  | Поиск доступного - выключен        |
| `SG_LOADBALANCE` | `true`   | Распределение нагрузки - включено  |
| `SG_LOADBALANCE` | `false`  | Распределение нагрузки - выключено |

```bash
# Выключить поиск быстрого по каждой стране
/container envs add list=MEOW key=SG_FASTEST value="false"

# Выключить поиск доступного по каждой стране
/container envs add list=MEOW key=SG_FAILOVER value="false"

# Выключить распределение нагрузки по каждой стране
/container envs add list=MEOW key=SG_LOADBALANCE value="false"
```

**Пример для страны US (США 🇺🇸):**

**Что добавляет stargate-area.sh:**

- 📋 Добавляет все созданные группы в главный SELECTOR для удобного управления

### Цепочки (Chain)

Специальный режим: трафик идет сначала через RU-сервер, потом в нужную страну. Полезно, если у вас белые списки или нужна иная логика маршрутизации.

Чтобы шаблон работал правильно, необходимо в контейнер положить ДВА файла, из которых он состоит.

  - Файл шаблона: [stargate-chain.yaml](templates/chain/stargate-chain.yaml)
  - Скрипт: [stargate-chain.sh](templates/chain/user_sh/stargate-chain.sh)

**Как это работает:**
```
Ваш компьютер
     ↓
  Русский прокси #1
     ↓
  Иностранный прокси #2
     ↓
Целевой сервер
```

**Что делает stargate-chain.sh:**
- 🔁 Собирает блоки подписок в формате, понимаемом ядром
- 🔗 Для каждой подписки `SUB*` создаёт дубль-провайдер `<имя>-via-ru`, у которого каждый узел получает `override: dialer-proxy: RU_AUTO` — то есть до иностранного сервера трафик идёт через российский
- 🚫 Российские узлы исключаются из цепочек на уровне провайдера (`exclude-filter`), чтобы не было петель
- 📦 Сохраняет провайдеры SRV и VETH из основного entrypoint.sh

**Как это работает в meow-rs 0.22:**
- `dialer-proxy` и `override.dialer-proxy` поддерживаются и на proxy-provider, и на отдельных прокси; цепочка строится ядром через внедрённый TCP-диалер (mihomo-модель). Имя фронт-хоста разрешается на каждый dial, `override` имеет приоритет над полем провайдера.
- Внутри `override:` ядро учитывает **только** `dialer-proxy`; `exclude-filter` и `exclude-type` ставьте на уровне провайдера (иначе они будут проигнорированы с предупреждением).
- Ограничения: `hysteria2` (QUIC) не умеет ехать по TCP-цепочке; `anytls` и внешние SIP003-плагины `ss` переходят на relay-обёртку. Провайдерские узлы не резолвятся как имя фронт-хоста (фронт — статический прокси или группа).
- 🔄 Группы `VIA_RU_FASTEST` / `VIA_RU_FAILOVER` / `VIA_RU_AUTO` выбирают между цепочками, `RU_AUTO` — группа с российскими узлами

**Особенности:**
- 🔗 Двойная маршрутизация для восстановления доступности интернета
- 🚀 Требует нескольких живых RU-прокси в подписках
- ⏱️ Пинг (задержка) будет больше - два прокси вместо одного
- 💾 Пик памяти 17.7 МБ по замеру; растёт вместе с числом подписок

**⚠️ Важно знать:**
- ⏱️ Из-за двойной маршрутизации пинг выше - онлайн-игры могут быть медленнее
- 📁 **Требует загрузки ДВУХ файлов**, а не одного
- 🔗 Цепочки строятся только для `SUB*`; провайдеры SRV/VETH подключаются напрямую (без цепочки)

**Установка:** файл шаблона и `.sh`-скрипт кладутся в папки `template/` и `user_sh/`,
затем задаётся `CONFIG`. Порядок шагов — в разделе
[«Шаблоны из двух файлов»](#шаблоны-из-двух-файлов-area-chain).
**Требования:**
- Несколько рабочих RU-прокси в подписках (для надежности)
- Закрытие неактивных UDP-соединений
- Достаточно ли у роутера памяти для удвоения подписок?

## Переключатели в панели

**Что это такое?** Переключатели (switches) - это как кнопки на панели управления. Они помогают выбрать, через какой именно прокси отправить трафик того или иного сервиса:
- Для YouTube можно выбрать один прокси
- Для Telegram - другой
- Для игр - третий

Некоторые переключатели вы настраиваете вручную, другие работают автоматически.

### Ручные переключатели

Их нужно настраивать самостоятельно в панели управления. **При первом запуске обязательно выберите прокси вручную:**

| Переключатель | Назначение                               | Что это значит                                                   |
| :------------ | :--------------------------------------- | :--------------------------------------------------------------- |
| `SELECTOR`    | **Главный** для большинства сервисов     | Для трафика, не распределяемого по сервисам                      |
| `MANUAL`      | Дополнительный выбор иностранного прокси | Если SELECTOR не подходит - выберите вручную здесь               |
| `RU_MANUAL`   | Дополнительный выбор российского прокси  | То же, но специально для RU-прокси                               |
| `XX_MANUAL`   | Выбор прокси конкретной страны           | Только Area шаблон (XX = US_MANUAL, DE_MANUAL, NL_MANUAL и т.д.) |

### Автоматические переключатели

Эти работают сами по себе. **Никогда их не трогайте в панели!** Если вы их измените, автоматика сломается.

**Типы Fallback** - они выбирают прокси автоматически:
- `AUTO` - сам выбирает лучший иностранный прокси
- `RU_AUTO` - сам выбирает рабочий российский прокси
- `XX_AUTO` - сам выбирает лучший прокси для страны X (только Area шаблон, где XX = код страны: US, DE, NL и т.д.)
- `VIA_RU_AUTO` - сам проводит трафик через РФ в заграницу **(только Chain шаблон)**
- `FAILOVER` / `RU_FAILOVER` / `XX_FAILOVER` - если основной прокси упал, автоматически переключаются на резервный

**Типы URLTest** - они выбирают НА ОСНОВЕ СКОРОСТИ:
- `FASTEST` - постоянно проверяет и использует САМЫЙ БЫСТРЫЙ иностранный прокси
- `RU_FASTEST` - САМЫЙ БЫСТРЫЙ российский прокси
- `XX_FASTEST` - САМЫЙ БЫСТРЫЙ прокси для страны X (только Area шаблон)
- `VIA_RU_FASTEST` - проверяет скорость и выбирает быстрейший путь через РФ в заграницу **(только Chain шаблон)**

**Типы Load-balance** - они РАСПРЕДЕЛЯЮТ НАГРУЗКУ:
- `LOADBALANCE` - распределяет нагрузку по иностранным серверам
- `RU_LOADBALANCE` - распределяет нагрузку по российским серверам

### Сломалась автоматика?

**Не волнуйтесь, это легко исправить:**

1. Откройте панель управления проксями
2. Найдите сбитый переключатель (около него отображается иконка замочка)
3. Нажмите на него **правой кнопкой мыши**
4. или нажмите кнопку спидометра

Тогда автоматика восстановится и все будет работать снова.

### Технические параметры (для любопытных)

**Tolerance в URLTest:** Это допуск задержки в миллисекундах - если разница между текущим и протестированным прокси меньше допуска, переключение не происходит.
- Текущее значение задается переменной окружения `TOLERANCE` (по умолчанию в Dockerfile — **10 мс**) и подставляется во все url-test-группы (AUTO/FASTEST)
- Уменьшите (например, до 5 мс), если хотите, чтобы прокси переключались более агрессивно (чаще)
- Увеличьте до 80-100 мс, если хотите большей стабильности

**Фильтрация РФ прокси:** Система ищет (регистр не важен):
- Флаг 🇷🇺 в названии
- Или текст "RU" (в названиях вида `RU Server` или `Russia` слово найдется как "RU")

Если в ваших прокси используются другие обозначения (вместо "RU"), отредактируйте фильтр `filter_ru` в шаблонах

**💡 Совет по свободной памяти роутера:** Если оставить панель управления открытой в браузере - она будет избыточно грузить память и ресурсы оборудования. Если закроете браузер или вкладку, когда ничего не настраиваете - сэкономите ~10 МБ ОЗУ. Не все агрессивные дашборды полезны.

## Оптимизация подписок

### Очистка подписок (рекомендуется)

Бесплатные подписки часто содержат рекламу, нерабочие и лишние узлы. Фильтр подписок убирает их до того, как они попадут в конфиг.

Используйте [фильтр подписок](https://github.com/Viktor45/fumox) для удаления:
- неработающих серверов
- опасных конфигураций
- мусорных данных
и для конвертации в реальном времени txt-подписок (url_list) в формат Clash/YAML.

Если ваши подписки уже чистые (платные), фильтр необязателен.

### Количество подписок

**Совет:** Используйте несколько разных подписок через `SUB1`, `SUB2`, `SUB3`:
- Повышает надежность (если одна подписка не загрузится)
- Больше вариантов для выбора прокси
- Критично для режима **Chain** (иначе может переключиться на прямое соединение по исчерпанию доступных серверов)

### Важные замечания

#### Кодировка

**Обязательно сохраняйте файлы шаблонов в UTF-8 без BOM:**
- Откройте конфиг в VS Code или другом редакторе
- Убедитесь в нижнем правом углу: `UTF-8` (не `UTF-8 with BOM`)
- BOM не даёт ядру распознать конфиг

#### Ограничения памяти

Все цифры по памяти и месту в этом документе сняты на `linux/amd64` (Docker Desktop, macOS) с одной подпиской на 30 прокси. Условия и метод замера описаны в разделе [«Потребление ресурсов (измерено)»](#потребление-ресурсов-измерено).

На самом маршрутизаторе (32-битный ARM) значения будут другими. Ориентируйтесь на порядок: Nano и Lite самые лёгкие, Area и Chain вдвое тяжелее, Full тяжелее всех и требует свободного места под геобазы.
